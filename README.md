# 质检承诺边界

一线踩出来的经验，不是又一个 YOLO Demo。

**[在线试用 → https://bianwuwei.github.io/vision-promise-boundary/](https://bianwuwei.github.io/vision-promise-boundary/)**

我在推进离散制造视觉／质检项目时发现，真正卡住交付的往往不是模型准不准，而是**报价和宣传阶段说的话有没有对齐产线的实际情况**——节拍没测就承诺检测速度、没有近两周误报样本就写进案例、脱敏截图客户根本没确认过能不能公开。这些坑我踩过，也见同行踩过。

这个工具把这些边界固化成一份可编辑的规则清单：填入当前谈单的场景（节拍、误报代价、样本、红线审批等），立刻得到「可以承诺 / 先缓一缓 / 直接拒单」三档结论。它不训练模型、不接摄像头、不做 agent——只帮你在报价和宣传稿定稿前，把话收干净。

面向：**正在评估视觉／质检供应商的甲方、正在谈落地的交付和销售团队**。

---

## 为什么会有这个东西

曾经在一个精密金属件外观检测的项目上，销售为了拿单，在客户会议室指着实验室 99.2% 的准确率，口头答应了「单件 120ms 节拍内完成全表面检出」。

到了真机上线才发现：车间振动导致图像必须加去模糊算法、工业相机多工位拼接吞吐打满，工控机在全分辨率推理下死活卡在 280ms。为了保节拍只能降输入分辨率，结果微米级划痕全漏报；想保精度就必须改多卡并行甚至重做机构，成本瞬间击穿交付预算，双方在产线边扯皮了整整三个月。

那次之后我定下死规矩：**没看到产线实测节拍与原始工况图前，绝不在技术方案里写死检测耗时与指标。** 这个工具，就是把这些拿真金白银和通宵改代码换来的教训，变成一道自动卡死冲动承诺的闸门。

## 这不是 YOLO Demo

市面上不缺「再训一个检测模型」的演示。落地卡点往往在别处：

- 客户要「检测速度」承诺，产线节拍数字还没对齐；
- 误报代价是停线／客诉，手里却没有近两周样本表；
- 宣传稿已经写好脱敏截图，客户从未确认能否上公众号；
- 无人批红线，交付口头答应了节拍内完成。

## 如果你正在评估一家视觉／质检供应商

打开试用页，把对方谈单时给你的承诺套进去，看它落在哪一档——这也是我自己在报价前会先跑一遍的检查。如果对方给你的承诺在这里会被判「拒单」，那值得当面追问一句为什么。

## 怎么用（交付／销售版）

1. 打开 [试用页](https://bianwuwei.github.io/vision-promise-boundary/)。
2. 左侧勾选／填写当前谈单场景（节拍、速度承诺、误报代价、样本、脱敏、红线等）。
3. 右侧即时得到三张清单；可点 **复制 Markdown** 贴进纪要或评审。
4. 需要演示「踩雷」时，点 **危险承诺预设**。

本地预览：

```bash
cd docs
python3 -m http.server 8080
# 浏览器打开 http://127.0.0.1:8080/
```

站点放在 `docs/`，GitHub Pages → `main` / `/docs`。

## 输出示例

**场景输入：**

- 产线实测节拍：未实测（仅有客户口头预估 200ms）
- 承诺检测速度：已承诺写入合同草案
- 误报代价：触发产线机械臂剔废
- 近两周连续良／废品样本：无

**系统输出判断（示意）：**

- **直接拒单／严禁承诺：** 严禁在未实测工况节拍前承诺耗时指标（对应规则：实验室推理速度不等于工控机全流水线耗时；无节拍数字却承诺速度／节拍内完成）。
- **先缓一缓：** 缺少连续生产样本，当前误报率预估极易引发批量误剔停线，需先行小批量采集打标。

打开试用页点 **危险承诺预设**，可看到完整三档清单与可复制 Markdown。

## 规则可编辑

规则在 [`docs/rules.json`](docs/rules.json)，每条包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 规则编号 |
| `when` | 条件（`all` / `any` + `eq` / `neq`） |
| `outcome` | `allow` \| `defer` \| `reject` |
| `message` | 中文说明 |

改完保存，刷新页面即生效（无需构建）。引擎在 [`docs/assets/app.js`](docs/assets/app.js)。

## 已知局限（v0.1）

- 部分规则会因同一根因（比如「无误报样本」）同时触发多条相近的暂缓／拒单理由，尚未去重和排序——下一步计划把「最该先补哪项证据」做成优先级排序输出。
- 规则引擎目前只支持 `all`/`any` + `eq`/`neq`，还不支持权重或「部分满足」。
